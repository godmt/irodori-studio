# Irodori Studio development instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Irodori Studio is a local-only SPA served by its FastAPI application from `dist/client`; it has no Sites, Cloudflare Pages, Worker, or static-hosting handoff. Do not add `.openai/hosting.json` or cloud-hosting build artifacts.

## Product decisions for this prototype

- `DESIGN.md` is the canonical product-wide visual and interaction policy. New UI must reuse its resource management, naming, deletion, typography, icon, feedback, and accessibility patterns before introducing a variant.
- Named resources use one interaction grammar: select/open, create, rename, and delete. Compact utility actions use icon-only Phosphor buttons with accessible names in the stable order create, rename, delete; core workflow actions may retain short text labels. Renaming always uses the shared name dialog, and destructive actions always use the shared confirmation dialog rather than browser `confirm`.
- Voice Library is a global Studio function available from every top-level workspace through the same header icon. Script and Live voice-name controls are both selectors only; clicking a voice name never opens settings in one workspace and selects it in another.
- Projects and trained models support explicit rename and delete operations. Project rename moves the existing saved project instead of creating an abandoned copy. Trained-model deletion is rejected while a voice profile references the asset.

- This is a desktop-first local production tool for Irodori-TTS, not a public hosted synthesizer.
- The Japanese display name of the Live workspace is `配信`. Do not expand it to `配信コンソール`; the shorter label is sufficiently clear in both the top navigation and workspace heading.
- The selected visual source is the supplied warm ivory/orange script editor: compact left navigation, large editable line cards, and a persistent bottom inspector.
- Core workflows must be real, not mocked: load a local checkpoint, queue synthesis, play one line or continuously from a selected line, reorder/duplicate/delete lines, and export production files.
- Streaming support means a low-friction live input queue with stop/interrupt and automatic playback.
- Video-production support means persistent projects, batch generation, a joined master WAV, per-line WAV files, SRT/VTT subtitles, CSV timing data, and an FFmpeg concat list.
- Project management is a user-facing create/open/delete workflow backed by server-owned local persistence. Never expose JSON import/export or other storage-format language in the Studio GUI. Preserve the current project before switching so opening another project never appears to discard the user's work.
- The Script workspace has one authoritative line list: the editable cards in the main stage. Do not duplicate those lines in the left sidebar, and do not add a sidebar "add line" action when the main list already provides "選択行の下に追加". Keep the sidebar for project summary, bulk text addition, and voice access.
- Production export belongs only to Script. Never place it in the shared header or expose it in Live; keep it as an icon-only floating action at the lower-right of the Script timeline.
- Japanese body text must remain comfortably readable; avoid tiny labels and low-contrast gray text.
- Use the project typography scale for Japanese UI: 16 CSS px or larger for body and explanatory text, 14 CSS px for constrained controls and supporting metadata, and never below 14 CSS px for Japanese. Decorative English eyebrows, timestamps and units may use 12 CSS px. Keep multiline Japanese at least 1.5 line-height and verify that 200% browser zoom does not clip, overlap or require horizontal reading scroll.
- Playback volume is a browser-local setting, available in both the script toolbar and Live console, and must affect all in-app playback without altering generated or exported audio files.
- Audio output routing is also browser-local. On Studio launch, request access using only the browser's native permission dialog, immediately stop the temporary input stream, then enumerate permitted output devices and expose them in the Live console so virtual audio cables can route playback into OBS. Never add a Studio-owned permission modal. If access is denied or routing is unsupported, lock playback to the system default without blocking the rest of the app. Apply the selected sink to all in-app playback and return to the system default when it disconnects.
- Keep the Live audio controls compact: the output-device and playback-volume icons replace redundant visible text labels. Preserve accessible names on the select and range input.
- Output devices are discovered from the browser permission result and selected only through the dropdown. Do not add device add, remove, refresh, or management buttons.
- Live audio controls must never overlap. Keep the closed output selector compact and truncate long device names; show the full names only in the opened dropdown. Keep the speaker icon directly adjacent to the volume slider without a placeholder label gap, and move the control group onto its own row at narrower widths.
- Show the same output-device selector and playback-volume control in both Script and Live. They are two views of one browser-local audio setting: changing either control must immediately update the other view and all in-app playback.
- Every script line exposes a refresh-icon action that adds and selects a new take using the current text, voice, and synthesis parameters without starting playback.
- The Script sidebar's current voice is the default for newly added and bulk-imported lines. Each existing line changes its own voice from the clickable voice-name dropdown; changing it marks existing takes for regeneration. When a line, capped-out take, or project is deleted, remove its unreferenced generated WAV and JSON metadata from `workspace/audio/`, while never deleting user-supplied reference WAVs or audio still referenced by another saved project.
- The server-owned shared Voice Library at `workspace/voices/profiles.json` is the source of truth for voice definitions, including Speaker Inversion, reference audio, LoRA, default caption and VOICEVOX publication settings. Voice edits auto-save independently of project saves. Projects keep a compatible snapshot and stable profile reference; restore by profile ID, with a unique exact-name match only for legacy migration. A Style ID and Speaker UUID stay stable across edits and restarts until the voice is explicitly deleted.
- Keep the shared Voice Library icon as the rightmost header action in every workspace. Its voice list is reordered by drag handle (with keyboard arrow fallback), persists that order in the shared library, and uses the same order in every voice selector after project switches and restarts.
- External speech clients use the separate local compatibility endpoint on `127.0.0.1:50021`; Studio and the compatibility API share the same resident model and FIFO synthesis queue.
- The voice library keeps its header visible and gives the modal body a dedicated vertical scroll area, so API details and save/delete actions remain reachable at ordinary desktop and mobile viewport heights.
- Use Phosphor Icons for interface icons. Do not substitute emoji or handcrafted SVG/CSS icons.
- The script and live text editors expose the official 45 Irodori performance emojis from an in-field Phosphor Smiley trigger. Insert at the remembered caret/selection, offer a compact common set before the full palette, and keep text emoji independent from Voice Design caption presets so both conditions can be used together.
- Script lines are reordered by drag only; do not restore redundant up/down buttons. The refresh icon creates and selects a new take with the current text, voice, and synthesis settings. Keep at most four takes per line, show the numbered take selector only when multiple takes exist, and make Play, Download, continuous playback, and export use the selected take.
- Script lines and Voice Library entries share one sortable-list interaction: drag only from the Phosphor handle, leave a fully empty source slot, render an opaque full-card drag overlay, and smoothly displace surrounding items toward the insertion gap. Keep Space/arrow/Space keyboard sorting and Escape cancellation; Escape during a modal drag cancels the drag without closing the modal. Respect reduced-motion preferences.
- Irodori-TTS is an external, user-configured repository. Do not vendor it, copy model/training code into Studio, or commit an absolute local path. Resolve it through `--irodori-root`, `IRODORI_TTS_PATH`, ignored `.studio/config.json`, or the sibling-folder fallback.
- `start-studio.ps1` owns local orchestration: frontend setup/build, Irodori environment selection, Studio API, model autoload, browser opening, and the VOICEVOX compatibility endpoint.
- Setup auto-detects the PyTorch backend from the selected Irodori-TTS `.venv` before using saved configuration or host hardware. Keep `-TorchBackend` as an explicit override for intentional environment changes; do not replace an already working Irodori environment based only on accelerator discovery.
- Recorder is a real top-level workspace under `src/features/recorder`. Its three recording stages are Irodori Starter 120, AICA Character Core 200, and AICA Full 500. Treat them as filtered views over one shared prompt root so Core recordings are reused in Full. The corpus control in the upper-left studio metadata area switches stages; it must not open a second copy of the right-side recording list. Recorder datasets are named, selected, created, renamed and deleted in Studio. Keep their opaque IDs stable for API and Training references, but persist them in human-readable, collision-safe name-based folders under `workspace/recordings/<dataset-name>/`; renaming changes the folder without breaking the ID. Save on recording and adoption; do not require a manual ZIP export between Recorder and Training. Training must select these datasets directly. Migrate legacy ID-named folders and legacy IndexedDB recordings safely. Recorder must use only the browser-native microphone permission prompt, never a Studio-owned permission modal. Preserve AICA upstream IDs, source, pinned version, CC0 notice, and the distinction between CC0 source text and newly recorded audio. Keep recorder code separable and preserve Script/Live project semantics as the remaining frontend is split into features.
- Long-audio ingestion accepts multiple local WAV, FLAC, MP3, M4A or other PyAV-readable single-speaker sources. Its primary workflow is `前処理 → 学習`; transcript correction and accept/exclude review are optional refinements, never a mandatory per-clip gate. Process bounded overlapping windows instead of creating or loading a whole uncompressed master, use VAD plus Japanese ASR, automatically accept clips that pass structural QC, retain rejected candidates for optional review, and commit only after the job completes. Preserve the original sources under `raw/`; use lossless FLAC only as a compact job-local intermediate, then atomically convert to 48 kHz mono PCM16 WAV under the selected dataset's `wavs/` and delete the FLAC only after the WAV and manifest commit succeed. Stable source-and-time IDs make reruns skip existing clips by default; explicit overwrite is the only mode that replaces them. Interrupted, failed and cancelled import jobs resume from validated candidate JSONL/FLAC checkpoints. Expose import history per learning dataset with resume and safe history deletion; deleting history removes only the job directory, never committed WAVs or dataset-owned RAW. Keep auditable source offsets and ASR/QC metrics, and let Training consume accepted imported clips exactly like microphone recordings.
- Recorder remains a corpus-recording workspace. Training owns the shared `学習データを用意する → 任意確認 → 学習` flow, including multi-file long-audio selection, preprocessing progress and optional transcript/acceptance review. Both entry paths write to the same user-visible learning dataset; Recorder may call the selector `収録先データセット`, but it must not create a second resource type. Treat format conversion, edge-only silence trimming and loudness normalization as method-independent dataset construction, while keeping model-specific latent/token/augmentation generation inside Training.
- Recorder and Training share one selected learning-dataset ID owned by the Studio shell. Changing the dataset in either workspace immediately changes the other workspace; navigation actions such as `コーパスを録音` only switch workspaces and must not carry a special one-off dataset override.
- Training is a real top-level workspace under `src/features/training`. Speaker Inversion is the recommended and initially selected method; LoRA is available as an explicitly advanced alternative, not a required step when Speaker Inversion is already sufficient. Default Speaker Inversion training to 500 steps and show 1000 steps or more as the in-field guidance for users seeking higher quality; treat an isolated pronunciation error as eligible for a same-checkpoint retake rather than proof that the checkpoint is undertrained. Default LoRA training to 1500 steps and show 3000 steps as the high-quality/tuning target. Scale the upstream 30k-step WSD warmup/stable/decay proportions to the chosen LoRA step count instead of leaving a 1000-step warmup on a short run. Models have user-facing names. Keep background job state, logs and temporary latents under `workspace/training/<job-id>/`, final Speaker Inversion assets under `workspace/models/speaker-embeddings/`, and final LoRA adapters under `workspace/models/lora/`. A completed asset keeps its own `studio-model.json` so its name and source dataset do not depend on disposable job history. Training consumes only accepted recording-dataset samples, releases the resident inference model before using the GPU, and invokes the configured external Irodori-TTS checkout instead of copying trainer code. It validates hashes and snapshots the already canonical dataset WAVs without trimming or normalizing them again. While training, show steps plus approximate `残り時間／全体時間`, based on step speed observed in the current trainer process; show a calculating state until a new step is observed and keep the estimate visibly approximate. Interrupted, failed and user-stopped jobs are resumable: valid snapshots and completed latent manifests are skipped, LoRA resumes full trainer state, and Speaker Inversion warm-starts from its latest periodic embedding. A normal resume writes into a new attempt without overwriting checkpoints; an explicit all-overwrite restart removes only job-generated artifacts and begins again from the source dataset.
- Before creating any CUDA training job, compare the GPU's nominal physical VRAM with Studio's method-and-precision recommendation: Speaker Inversion uses 12 GB for BF16/FP16 and 16 GB for FP32; LoRA uses 24 GB for BF16/FP16 and 32 GB for FP32. If it is lower, use the shared confirmation dialog to explain likely shared-memory spill, extreme slowdown or startup failure. Treat a reported 11.99 GiB as a nominal 12 GB card. Cancelling must neither create a job nor unload the resident inference model; explicit continuation remains available because these are conservative recommendations rather than hard hardware blocks.
- Launch Training and long-audio preprocessing workers in isolated process groups. A user stop must terminate and wait for the complete worker tree so child trainers cannot retain CPU, RAM or CUDA/VRAM resources. Speaker Inversion and LoRA use the same cancellation path; changing only the visible job state is not a successful stop.
- Learning data follows a product-wide three-layer contract independent of Irodori-TTS: immutable user/source data under dataset `raw/`; versioned, method-independent canonical samples under `wavs/`; and model-specific features/checkpoints under the training job. On microphone save and imported-clip commit, produce 48 kHz mono PCM16 WAV, trim only leading/trailing silence using a -45 dBFS threshold with 10 ms windows and 180 ms boundary padding, preserve every internal pause, and normalize to -16 LUFS with peak safety. Persist pipeline version, source/output hashes and per-operation results on each recording. Reuse valid current outputs by default and rebuild from RAW only after version change, corruption or explicit overwrite. Never overwrite RAW and never apply the common transforms again during model training.
- Studio-owned prepared WAVs must not depend on TorchCodec or a system FFmpeg installation merely to enter Irodori-TTS training. Decode only the validated job-local PCM WAV boundary through Studio's compatibility runner, require every accepted row and latent before starting training, and never treat an empty or partial manifest as success. Failed jobs expose a short cause and recovery action in the history, with the local technical log available on demand.
